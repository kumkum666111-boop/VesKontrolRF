# ВесКонтроль РФ 4.0 — калькулятор осевой нагрузки

Тёмное Android-приложение на Kotlin + Jetpack Compose. Главный сценарий — расчёт нормативной нагрузки по каждой оси и по группам сближенных осей, плюс проверка общей массы.

## Реализовано
- Выбор типа транспортного средства: легковой автомобиль, одиночный грузовик, автопоезд, отдельный прицеп, автобус, сочленённый автобус, другое.
- Количество осей от 1 до 12.
- Категория дороги I-а/I-б/II/III/IV/V.
- Отдельный выбор нормативной осевой нагрузки 6 / 10 / 11,5 т/ось.
- Указание ограничения на ось с дорожного знака — оно имеет приоритет над табличными значениями.
- Для каждой оси: фактическая нагрузка, число колёсных сборок, односкатная/двускатная ошиновка, межосевое расстояние, индивидуальный предел из документов ТС.
- Автоматическое формирование групп сближенных осей по расстоянию до 2,5 м.
- Учёт среднего межосевого расстояния внутри группы.
- Раздельная проверка предела отдельной оси и суммарного предела сдвоенной/строенной группы.
- Проверка полной массы автомобиля/автопоезда по приложению № 3 к Постановлению № 2060 для типов, перечисленных в таблице.
- Для легковых автомобилей и отдельного прицепа — ручной ввод ограничения из ПТС/СТС/таблички изготовителя.
- Порог предупреждения 90%, уведомления Android при приближении к лимиту/превышении.
- Сохранение введённых параметров.
- Справка по последствиям перегруза и административной ответственности.
- 20 unit-тестов логики таблиц и расчётов.
- GitHub Actions workflow для тестов и сборки APK.

## Юридическая модель
Основная таблица: Постановление Правительства РФ от 01.12.2023 № 2060, приложение № 2. Значения зависят от расчётного норматива дороги 6/10/11,5 т/ось, конфигурации колес, односкатной/двускатной ошиновки и средней дистанции между осями группы. Приложение № 3 задаёт предел полной массы для одиночных автомобилей, автопоездов и автобусов по числу осей.

Категория дороги (I-а, I-б, II, III, IV, V) вводится отдельно как справочная характеристика. Она сама по себе не всегда определяет осевой предел. Пользователь должен выбрать расчётный норматив из достоверных дорожных данных либо ввести ограничение с дорожного знака. Для поездки нужно соблюдать наиболее строгое из применимых ограничений: норматив дороги, знак, документы ТС, спецразрешение, ограничения маршрута/моста.

## Сборка
Требуются Android Studio с поддержкой Android 16 SDK, JDK 17, Android SDK Platform 36 и Build Tools 36.0.0.
1. Распакуйте архив.
2. Откройте корень `VesKontrolRF_4` в Android Studio.
3. Выполните Gradle Sync.
4. Запустите `app` на Android или выберите Build → Build Bundle(s) / APK(s) → Build APK(s).

Проект использует Android Gradle Plugin 8.13.2, Gradle 8.13 и JDK 17. Готовый Gradle Wrapper JAR в архив не включён, поэтому локально запускайте сборку установленным Gradle 8.13 (`gradle :app:assembleDebug`) либо используйте GitHub Actions ниже.

## GitHub Actions — рекомендуемый способ получить APK
1. Создайте пустой репозиторий GitHub.
2. Загрузите в него **содержимое** этой папки (так, чтобы `app/`, `build.gradle.kts` и `.github/` лежали в корне репозитория).
3. Откройте вкладку **Actions** и запустите workflow **Android build and tests** (он также запускается при push в `main`/`master`).
4. После успешного выполнения откройте запуск workflow и скачайте артефакт `VesKontrolRF-debug-apk`. Внутри будет `app-debug.apk`.

Workflow устанавливает JDK 17, Android SDK 36 и Gradle 8.13, запускает тесты, затем собирает debug APK.

## Проверки, выполненные при подготовке архива
- Расчётный Kotlin-модуль `AxleRules.kt` скомпилирован локальным Kotlin compiler.
- Все 20 тестовых методов расчётного модуля выполнены отдельно: 20 passed, 0 failed.
- XML-файлы Android-манифеста, темы и иконки проверены на корректный XML-синтаксис.
- Полную Android-сборку и APK в этой среде выполнить не удалось: здесь отсутствуют Android SDK, Gradle distribution и сетевой доступ для их установки. Поэтому архив не выдаётся за уже собранный APK; фактическую проверку Android-компиляции выполнит указанный GitHub Actions workflow.

## Ограничения
- Это предварительный справочный калькулятор, не сертифицированное средство измерения.
- Нет автоопределения нормативной дороги, дорожных знаков, временных ограничений и параметров моста.
- Нет интеграции с весами или реестрами транспортных средств.
- Значения должны сверяться с действующими документами и официальными данными владельца конкретной дороги.
- Расчёт не является юридическим разрешением на движение тяжеловесного ТС.
